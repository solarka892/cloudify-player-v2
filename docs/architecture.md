# Как устроен Cloudify

Приложение — это две половины, которые разговаривают друг с другом.

```
┌──────────────────────────── окно приложения ────────────────────────────┐
│                                                                          │
│   Фронтенд (React, TypeScript)          то, что видно и что нажимают     │
│        │                                                                 │
│        │  команды: invoke("search_tracks", { q })  →  ответ JSON          │
│        ▼                                                                 │
│   Tauri (Rust, папка src-tauri)         окно, вход, хранилище, загрузки  │
│        │                                                                 │
│        ▼                                                                 │
│   crates/soundcloud (Rust)              всё общение с SoundCloud          │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

## Rust

### `crates/soundcloud` — связь с SoundCloud

Отдельная библиотека (crate — так в Rust называют пакет кода). Только она знает
адреса SoundCloud, умеет доставать `client_id`, ходить по страницам списков и
понимать ответы. Остальное приложение зовёт её функции вроде
`client.search_tracks(...)` и получает готовые структуры: `Track`, `User`,
`Playlist`.

Почему отдельно: SoundCloud может поменять свой API в любой день. Когда это
случится, чинить придётся в одном месте. А ещё эту библиотеку можно проверять
тестами без окна и без интерфейса.

Что SoundCloud отвечает и где у него подвохи — в
[soundcloud-api.md](soundcloud-api.md).

### `crates/diary` — дневник прослушиваний

Своя база SQLite (`diary.sqlite3` в папке данных приложения, больше нигде):
каждое прослушивание, чем оно закончилось и обстановка вокруг него — часть
суток, день недели, сезон, длина светового дня, рассвет, закат и высота
солнца. Солнце считается формулами Астрономического альманаха по дате и
широте, без интернета, и сверено с таблицами USNO (тесты). Город, пока его не
назвали, берётся из часового пояса: таблица `zones.rs` сделана из `zone.tab`
базы часовых поясов tzdb.

Почему отдельно: про SoundCloud дневник ничего не знает, а «Подборка» учится
на нём. Его можно проверять тестами без окна.

Для подборки (`taste.rs`) дневник отдаёт все закрытые прослушивания строчками
из чисел (трек, артист, когда, чем закончилось, сколько услышано) и треки,
которые можно предложить снова: недавно дослушанные (от них растут станции),
прошлой зимы, этой недели год назад и дослушанные не раз. Окна считаются по
местному календарю и полушарию города. Сколько весит пропуск или дослушивание,
решает не дневник, а правила подборки во фронтенде.

### `src-tauri` — само приложение

- `commands/` — команды, которые может вызвать фронтенд. Каждая команда
  тонкая: взяла аргументы → позвала нужный модуль → вернула ответ или
  понятную ошибку (`error.rs`: одна форма ошибки на всё приложение).
- `state.rs` — общий клиент SoundCloud; токен из связки ключей читается один
  раз за запуск, первой командой, которой он нужен.
- `keychain.rs` — токен в системной связке ключей (keyring) и больше нигде.
- `signin.rs` — вход через окно SoundCloud: отдельное окно без доступа к
  командам приложения, cookie `oauth_token` читается из Rust.
- вход в аккаунт и хранение токена в системной связке ключей (keyring);
- `diary_file.rs` и `commands/diary.rs` — дневник: файл открывается при
  старте (прослушивания, оборванные выходом, закрываются как «остановил»),
  если не открылся — приложение играет дальше, а дневник говорит почему;
- потом: зеркало библиотеки для офлайн-поиска;
- загрузки треков для офлайна;
- тексты песен (LRCLIB).

## Фронтенд

```
src/
├── api/        единственное место, которое вызывает Rust (invoke)
├── dev/        только для разработки: заменяет Rust в обычной вкладке браузера
├── app/        оболочка: окно, навигация, общие провайдеры
├── features/   экраны и их логика: player, library, search, settings…
├── ui/         общие кирпичики интерфейса: кнопки, списки, слайдеры
└── styles/     токены дизайна (цвета, шрифты, отступы) и общий CSS
```

- **Данные с SoundCloud** (лайки, поиск, плейлисты) живут в TanStack Query: он
  сам помнит уже загруженное, не делает один запрос дважды и умеет
  подгружать списки страницами.
- **Состояние приложения** (что играет, очередь, громкость, настройки) — в
  Zustand, небольших хранилищах по одному на тему.
- **Звук** играет в самом окне: `<audio>` + Web Audio (эквалайзер, кроссфейд),
  `hls.js` для треков, которые SoundCloud отдаёт кусками.
- **«Подборка» считается своим движком** (`features/selection/`), без нейросети
  и без сети: `engine.ts` — кандидаты из источников, оценка по дневнику и
  очередь с балансом знакомого и нового; одинаковое «зерно» (seed) даёт
  одинаковую очередь, а с пустым дневником — ровно очередь первой версии (тест
  сверяет с замороженной копией). `taste.ts` превращает строчки дневника в
  счёт для трека и артиста, `why.ts` — факты в строку «почему». Данные
  собирает один раз оболочка (`useSelection.ts`: лайки, история, станции и
  похожие от дослушанного, дневник), `session.ts` помнит нажатия «больше
  такого» и «не то» и подбирает заново то, что дальше. Обстановка (ночь, зима,
  короткий день) потом войдёт в тот же счёт ещё одним слагаемым.
- **Дневник пишет** `features/diary/record.ts`: плеер говорит, почему ушёл с
  трека (`onLeave` в `features/player/store.ts`), а записыватель по очереди
  отправляет в Rust начало (с первого услышанного звука), прогресс и конец
  каждого прослушивания.
- **Ошибки** слышны в одном месте — в кэше TanStack Query
  (`features/problems/watch.ts`). Упавший запрос становится «проблемой» с
  простыми словами (`words.ts`) в списке «Что не так» (`store.ts`), удачный
  повтор её снимает. Нет сети и устаревший вход — отдельные состояния
  (`useConnection`), от них сереет свет. Действие, которое не прошло (лайк,
  радио), сообщает о себе само через `actionFailed`.
- **Сломанная часть не роняет окно**: страницы, разделы, полки, части главной и
  плеер обёрнуты в `Part` (граница ошибок React). Упавшая часть показывает
  свои пустые рамки, остальное работает.
- **В браузере ломать можно нарочно**: `?fail=my_playlists:api` в адресе или
  `localStorage["cloudify.dev.fail"]` — заглушка ответит, как SoundCloud при
  поломке (см. `src/dev/backend.ts`).

## Правила

1. **Про SoundCloud знает только `crates/soundcloud`.** Фронтенд не видит
   адресов API и не ходит туда сам.
2. **Каждая команда Rust — один файл-двойник в `src/api/`** с типами. Поменял
   ответ в Rust — поменяй тип в TypeScript.
3. **Ошибки — понятные.** Не «Error 403», а «SoundCloud не пустил (защита от
   ботов)» или «вход устарел — войди заново».
4. **Одна сломанная функция не роняет приложение.** Сломался поиск — плеер и
   библиотека работают.
5. **Секреты не пишем никуда.** Токен — только в keyring. В логах нет токенов и
   заголовков авторизации. `client_id` не хранится в коде.
6. **Без интернета для себя.** Шрифты и всё остальное лежит внутри
   приложения, никаких CDN. Наружу ходим только в SoundCloud и LRCLIB.
7. **Код из старой версии не берём.** Из `cloudify-old` переносятся только
   функции (что приложение умеет), всё пишется заново.
