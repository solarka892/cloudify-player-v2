# Как устроен Cloudify

Приложение — это две половины, которые разговаривают друг с другом.

```
┌──────────────────────────── окно приложения ────────────────────────────┐
│                                                                          │
│   Фронтенд (React, TypeScript)          то, что видно и что нажимают     │
│        │                                                                 │
│        │  команды: invoke("search_tracks", { q })  →  ответ JSON          │
│        ▼                                                                 │
│   Tauri (Rust, папка src-tauri)         окно, вход, хранилище, загрузки  │
│        │                                                                 │
│        ▼                                                                 │
│   crates/soundcloud (Rust)              всё общение с SoundCloud          │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

## Rust

### `crates/soundcloud` — связь с SoundCloud

Отдельная библиотека (crate — так в Rust называют пакет кода). Только она знает
адреса SoundCloud, умеет доставать `client_id`, ходить по страницам списков и
понимать ответы. Остальное приложение зовёт её функции вроде
`client.search_tracks(...)` и получает готовые структуры: `Track`, `User`,
`Playlist`.

Почему отдельно: SoundCloud может поменять свой API в любой день. Когда это
случится, чинить придётся в одном месте. А ещё эту библиотеку можно проверять
тестами без окна и без интерфейса.

Что SoundCloud отвечает и где у него подвохи — в
[soundcloud-api.md](soundcloud-api.md).

### `src-tauri` — само приложение

- `commands/` — команды, которые может вызвать фронтенд. Каждая команда
  тонкая: взяла аргументы → позвала нужный модуль → вернула ответ или
  понятную ошибку (`error.rs`: одна форма ошибки на всё приложение).
- `state.rs` — общий клиент SoundCloud; токен из связки ключей читается один
  раз за запуск, первой командой, которой он нужен.
- `keychain.rs` — токен в системной связке ключей (keyring) и больше нигде.
- `signin.rs` — вход через окно SoundCloud: отдельное окно без доступа к
  командам приложения, cookie `oauth_token` читается из Rust.
- вход в аккаунт и хранение токена в системной связке ключей (keyring);
- локальная база SQLite: история, метки, зеркало библиотеки для офлайн-поиска;
- загрузки треков для офлайна;
- тексты песен (LRCLIB).

## Фронтенд

```
src/
├── api/        единственное место, которое вызывает Rust (invoke)
├── dev/        только для разработки: заменяет Rust в обычной вкладке браузера
├── app/        оболочка: окно, навигация, общие провайдеры
├── features/   экраны и их логика: player, library, search, settings…
├── ui/         общие кирпичики интерфейса: кнопки, списки, слайдеры
└── styles/     токены дизайна (цвета, шрифты, отступы) и общий CSS
```

- **Данные с SoundCloud** (лайки, поиск, плейлисты) живут в TanStack Query: он
  сам помнит уже загруженное, не делает один запрос дважды и умеет
  подгружать списки страницами.
- **Состояние приложения** (что играет, очередь, громкость, настройки) — в
  Zustand, небольших хранилищах по одному на тему.
- **Звук** играет в самом окне: `<audio>` + Web Audio (эквалайзер, кроссфейд),
  `hls.js` для треков, которые SoundCloud отдаёт кусками.

## Правила

1. **Про SoundCloud знает только `crates/soundcloud`.** Фронтенд не видит
   адресов API и не ходит туда сам.
2. **Каждая команда Rust — один файл-двойник в `src/api/`** с типами. Поменял
   ответ в Rust — поменяй тип в TypeScript.
3. **Ошибки — понятные.** Не «Error 403», а «SoundCloud не пустил (защита от
   ботов)» или «вход устарел — войди заново».
4. **Одна сломанная функция не роняет приложение.** Сломался поиск — плеер и
   библиотека работают.
5. **Секреты не пишем никуда.** Токен — только в keyring. В логах нет токенов и
   заголовков авторизации. `client_id` не хранится в коде.
6. **Без интернета для себя.** Шрифты и всё остальное лежит внутри
   приложения, никаких CDN. Наружу ходим только в SoundCloud и LRCLIB.
7. **Код из старой версии не берём.** Из `cloudify-old` переносятся только
   функции (что приложение умеет), всё пишется заново.
